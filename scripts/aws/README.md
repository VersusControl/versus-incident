# versus-reader role for AWS

Versus reads AWS resource *metadata* through a role it assumes in your account:
`versus-reader`. This directory holds three ways to create it — a
CloudFormation template for the console, a Terraform module for pipelines, and a CLI script with policy files
for terminals (`cli/`). All three produce the same role, trust condition and
permissions; the lint test fails if they drift.

For the management (payer) account of an AWS Organization there is a second,
cost-only role, `versus-cost-reader`; see
[Cost-only role for a management account](#cost-only-role-for-a-management-account).

What the role can do:

- **Read metadata** with an explicit allow list of `Describe*`, `List*` and
  configuration calls for API Gateway, Auto Scaling, AWS Health,
  CloudFormation, CloudFront, CloudTrail, CloudWatch alarms, AWS Config
  recorders, DynamoDB tables, EC2, ECS, EKS, ElastiCache, Elastic Load
  Balancing, EventBridge, IAM roles, Kinesis, Lambda configuration, RDS,
  Route 53, S3 bucket metadata and security flags, SNS, SQS, Step Functions,
  Resource Explorer, Service Catalog AppRegistry applications and their
  associated resources, and the resource tag API.
- **Nothing else.** No `Put`, `Create`, `Update`, `Delete`, `Run` or
  `Invoke` action is allowed anywhere, and the deny list below wins over any
  allow.

## CloudFormation quick create (console, 5 steps)

1. Open **CloudFormation → Create stack → With new resources (standard)** in
   the account and Region the role belongs to.
2. Choose **Upload a template file**, select `versus-reader.yaml`, then
   **Next**.
3. Fill the parameters, then **Next**:
   - **VersusPrincipalArn** — the exact Versus role ARN shown in the Versus
     connect wizard, e.g. `arn:aws:iam::123456789012:role/versus-app`. Use that
     role ARN only; do **not** use the account root
     (`arn:aws:iam::123456789012:root`), because trusting an account root lets
     every principal in the Versus account assume this role.
   - **ExternalId** — the secret string displayed next to the principal in
     Versus. Copy it exactly; it is at least 16 characters and the stack fails
     validation if it contains spaces or is shorter.
   - **OptionalData** — leave `off` unless you want cost, posture and check
     data (see below).
4. On the review page, acknowledge **I create an IAM resource**, then
   **Submit**. Wait for `CREATE_COMPLETE` (about 20 seconds).
5. Open the **Outputs** tab, copy **RoleArn**, paste it into the Versus
   connect wizard, and run the access check. Versus calls
   `sts:AssumeRole` and probes each service; anything denied is reported with
   a copyable fix policy.

To change the principal, the ExternalId or the optional-data setting, update
the stack with the new parameter values — the role is replaced in place with
no other resource involved. To revoke access, delete the stack.

## Why ExternalId exists

`sts:AssumeRole` alone would let Versus (or anyone who learns the Versus
principal ARN) assume the role in *every* account that trusts that principal.
The `ExternalId` is a per-customer secret generated by Versus and shared only
with you. The trust policy requires both the principal ARN *and* the exact
ExternalId value, so a confused-deputy call with the right ARN but the wrong
ExternalId is rejected by AWS before any permission is evaluated.

The value is a credential: anyone with both the ARN and the ExternalId can
read what the role can read, until you rotate it. Rotating means generating a
new ExternalId in Versus and updating this stack with the new value.
CloudFormation stores parameters, so the ExternalId is marked `NoEcho` only to
keep it out of console output — treat it like a password, and do not put it in
a Terraform state file you share more widely than the credentials.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `VersusPrincipalArn` fails validation with "must be the exact Versus IAM role ARN" | The value is an account root ARN, an IAM user ARN, or a malformed role ARN | Copy the Versus **role** ARN from the connect wizard, `arn:aws:iam::<account-id>:role/<role-name>` |
| `ExternalId` fails validation | Fewer than 16 characters, more than 1224, or contains a space | Copy the full ExternalId from the wizard unchanged |
| `sts:AssumeRole` returns `AccessDenied` with the right ExternalId | The role ARN in Versus does not match `VersusPrincipalArn` exactly | Set `VersusPrincipalArn` to the same role ARN the wizard shows, then update the stack |
| Terraform plan rejects `versus_principal_arn` | Same rule as CloudFormation: the module accepts a role ARN only | Pass the Versus role ARN, never the account root |

## OptionalData toggle

`OptionalData` defaults to `off` and adds one extra statement:

| What | Actions |
|---|---|
| Cost Explorer (global, billed per request) | `ce:GetCostAndUsage`, `ce:GetCostAndUsageWithResources`, `ce:GetCostForecast`, `ce:GetSavingsPlansCoverage` |
| Cost allocation tags (free) | `ce:ListCostAllocationTags` |
| AWS Budgets definitions | `budgets:ViewBudget` |
| Rightsizing and idle advice | `cost-optimization-hub:ListRecommendations`, `compute-optimizer:GetEC2InstanceRecommendations` |
| Security Hub findings | `securityhub:GetFindings` |
| AWS Config advanced query | `config:SelectResourceConfig` |
| Trusted Advisor checks | `trustedadvisor:Describe*` |

Turn it on only for the FinOps and posture features. Cost Explorer charges
about $0.01 per request, so enabling it means Versus polling cost data on your
account's bill (Versus caps this at 20 paid requests a day per deployment by
default). In Terraform the same switch is `optional_data = true`.

## What each deny protects

These are explicit `Deny` statements, so they cannot be overridden by another
policy that later grants a broader action on the same role.

| Deny | What it stops |
|---|---|
| `s3:GetObject` | Reading object bodies stored in your buckets |
| `secretsmanager:GetSecretValue` | Reading secret values |
| `ssm:GetParameter*` | Reading Parameter Store values, including `SecureString` |
| `kms:Decrypt` | Decrypting ciphertext with your keys |
| `dynamodb:GetItem`, `dynamodb:Query`, `dynamodb:Scan` | Reading table items |
| `lambda:GetFunction` | Downloading function code (configuration reads stay allowed) |
| `ec2:GetConsoleOutput` | Reading instance console output, which can contain boot-time secrets |
| `logs:GetLogEvents` | Reading log bodies |

A second deny keeps the billing account surfaces out: `account:*`,
`aws-portal:*`, `billing:*`, `consolidatedbilling:*`, `invoicing:*`,
`payments:*`, `purchase-orders:*` and `tax:*`. Cost figures come from Cost
Explorer only, never from billing account details, invoices, payment methods,
tax registrations or account settings.

## Cost-only role for a management account

When the cost source is the management (payer) account of an Organization,
create `versus-cost-reader` there instead of `versus-reader`. The management
account controls the whole Organization, so this role reads cost for every
linked account and nothing else:

- **Allowed:** exactly the cost reads in the OptionalData table above —
  `ce:GetCostAndUsage`, `ce:GetCostAndUsageWithResources`,
  `ce:GetCostForecast`, `ce:GetSavingsPlansCoverage`,
  `ce:ListCostAllocationTags`, `budgets:ViewBudget`,
  `cost-optimization-hub:ListRecommendations` and
  `compute-optimizer:GetEC2InstanceRecommendations`. They are always on; there is no
  OptionalData switch.
- **Denied:** every other action, through a `Deny` with `NotAction` set to the
  cost reads, so a broader policy attached later cannot add inventory, change
  history or anything else. The billing deny above is repeated as its own
  statement.
- **Not included:** inventory, CloudTrail and other `versus-reader` reads.
  Connect member accounts with `versus-reader` to get the *Why* for their
  cost.

The trust policy and parameters are the same as `versus-reader`: the exact
Versus role ARN (not the account root) and the ExternalId.

CloudFormation: create a stack in the management account from
`versus-cost-reader.yaml` with **VersusPrincipalArn** and **ExternalId**, then
copy **RoleArn** from the Outputs tab into the Versus connect wizard as the
cost source. Terraform:

```bash
cd terraform/versus-cost-reader
terraform init
terraform apply \
  -var 'versus_principal_arn=arn:aws:iam::123456789012:role/versus-app' \
  -var 'external_id=<from the Versus wizard>'
terraform output -raw role_arn
```

Remove it with `terraform destroy` or by deleting the stack. There is no CLI
script for this role.

## CLI

`cli/` holds the same role as a shell script plus three policy files, for
terminals and automation:

```bash
cd scripts/aws/cli
./create-versus-reader.sh <versus-principal-role-arn> <external-id> [--optional-data]
```

It validates the principal (a role ARN only), refuses a short or spaced
External ID, updates the trust policy when the role already exists, never echoes
the External ID, and prints the role ARN plus a verification command. The manual
`aws iam` equivalent and the removal commands are in
[cli/README.md](cli/README.md).

## Terraform

```bash
cd terraform/versus-reader
terraform init
terraform apply \
  -var 'versus_principal_arn=arn:aws:iam::123456789012:role/versus-app' \
  -var 'external_id=<from the Versus wizard>' \
  -var 'optional_data=false'
terraform output -raw role_arn
```

`external_id` is marked sensitive. Prefer a `TF_VAR_external_id` environment
variable or a secret manager over `-var` on a shared shell, and keep the state
in an encrypted backend.

## Drift check

`validate_test.go` in this directory parses the templates, the Terraform
modules and the CLI policy files of both roles. It fails on any allow action
outside the catalog or cost list, any action that is not a read, any missing
deny, a trust policy without `sts:ExternalId`, optional actions that are not
gated by `OptionalData`, or a `versus-cost-reader` action outside the cost
list (allow or `NotAction`):

```bash
cd scripts/aws && go test ./... -count=1
gofmt -l scripts/aws
terraform fmt -check -recursive scripts/aws/terraform
```
